# 家庭节奏

一套部署在自己家庭服务器里的家庭日程与积分奖励系统。家长安排成长任务、审核完成情况；孩子查看每日日程、完成任务、积累积分并兑换心愿。

数据保存在本地 SQLite 文件中，不依赖第三方云服务。界面按手机、iPad 和桌面浏览器设计。

## 任务规则

| 任务类型 | 创建与生效 | 修改规则 | 完成与积分 |
| --- | --- | --- | --- |
| 约定任务 | 家长创建，孩子接受后生效 | 清单由家长维护；家长修改后孩子需要重新接受 | 孩子按约定频次上报成果，家长验收通过后获得积分 |
| 自建任务 | 孩子创建，家长审核通过后生效 | 孩子可以修改自己创建的任务；修改已生效任务后会重新进入家长审核 | 按审核后的频次上报成果，家长验收通过后获得积分 |

完成上报支持文字说明和一张成果照片，照片会压缩后保存在家庭服务器的 `data/uploads/` 中。约定任务清单不会开放给孩子编辑，服务端也会校验权限，而不只是隐藏界面按钮。

## 已实现

- 多用户家庭：家长和孩子使用各自密码登录，家庭数据互相隔离。
- 今日日程：今日进度、成员进度、积分余额和最近积分变化。
- 约定任务：家长创建并设置频次与奖励，孩子接受后才生效；孩子不能修改约定清单。
- 自建任务：孩子可以提出任务、频次和期望积分，家长审核通过后才进入日程。
- 重复日程：单次、每天、工作日、每周指定日期，可设截止时间、分类和积分。
- 成果验收：孩子按频次提交完成说明，可附手机拍摄的成果照片；家长通过后积分到账。
- 行为扣分：家长创建扣分项并设置警告次数和扣分值，孩子接受后生效；默认前 3 次警告，警告用完后按次扣分，并保留完整记录。
- 积分体系：每笔增加和扣除都有原因与余额记录，家长也可手动调整。
- 心愿奖励：奖励库存、所需积分、兑换申请、家长兑现或退回、取消退款。
- 家庭报告：7 天完成趋势、各成员完成率、积分和家庭累计数据。
- 成员账户：每位家长和孩子都能上传自己的照片头像、更换或移除照片、修改密码。
- 家庭管理：添加家长/孩子、修改称呼、重置密码、停用成员、创建或删除日程。
- 私有部署：SQLite、本地静态资源、无外部依赖、PWA 图标和离线应用外壳。

## 快速启动

需要 **Node.js 22.5 或更高版本**，推荐 Node.js 24。项目没有第三方 npm 依赖。

```powershell
node server.js
```

打开 <http://localhost:3000>，按首次设置页面创建家庭。服务会同时监听局域网地址，终端启动时会打印类似：

```text
局域网访问：http://192.168.1.10:3000
```

手机或 iPad 连接同一个 Wi-Fi 后访问该地址即可。在 Safari 中选择“添加到主屏幕”，可以获得接近原生应用的入口。

开发时可以使用：

```powershell
node --watch server.js
```

运行自动化测试：

```powershell
node --test
```

## Docker 部署

安装 Docker 后，在项目目录运行：

```bash
docker compose up -d --build
```

默认访问地址是 `http://家庭服务器IP:3000`。数据库会持久化到当前目录的 `data/family.db`，重建容器不会丢失。

如需修改端口，先复制 `.env.example` 为 `.env`，再修改 `APP_PORT`。

```bash
docker compose logs -f
docker compose restart
```

## 建议使用 HTTPS

局域网 HTTP 已经可以正常使用，但安全 Cookie 和完整的 PWA 安装能力通常需要 HTTPS。家庭服务器可以通过 Caddy、Nginx、群晖反向代理或 Tailscale 提供安全访问。

`deploy/HTTPS.md` 包含群晖、威联通和 Caddy 的完整 HTTPS 配置步骤，`deploy/Caddyfile.example` 给出了 Caddy 配置示例。启用 HTTPS 后，同时设置：

```yaml
environment:
  COOKIE_SECURE: "true"
```

不要把 `3000` 端口直接暴露到公网。需要跨网络访问时，优先使用 Tailscale、WireGuard 等家庭 VPN。

## 数据备份与恢复

SQLite 文件位于 `data/family.db`。建议每天预约一次在线备份：

```powershell
node scripts/backup.js
```

备份会写到 `data/backups/`，同时备份 `data/uploads/` 中的成果照片。可以把整个 `data` 目录同步到 NAS 的另一块磁盘，但不要只复制正在写入的数据库文件；使用备份脚本更安全。

恢复时停止服务，将选定的数据库备份复制为 `data/family.db`，并把对应时间戳的 `uploads-*` 目录恢复为 `data/uploads`，再重新启动。也可以设置 `DB_PATH` 指向其他位置。

家长忘记密码时，停止服务并运行：

```powershell
$env:NEW_PIN="新的4到8位数字"
node scripts/reset-pin.js "爸爸"
```

脚本会同时清除该成员的旧登录会话。不要将密码放入会公开保存的脚本或聊天记录。

## 可配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址，家庭局域网访问需保持默认 |
| `DB_PATH` | `data/family.db` | SQLite 数据库路径 |
| `UPLOAD_DIR` | 数据库目录下的 `uploads/` | 成果照片保存目录 |
| `COOKIE_SECURE` | `false` | 使用 HTTPS 时设为 `true` |

## 积分机制建议

1. **小步、稳定**：每天 3–5 个核心任务即可。积分宁可小而稳定，不要用一次大额奖励制造压力。
2. **奖励过程**：除了结果，也给“主动开始”“自己检查”“遇到困难后重试”加分，让孩子看到可复制的行为。
3. **避免罚分绑定情绪**：没完成时先找原因，积分规则照常执行，但不要临场扣分惩罚。家长手动减分应少用，并写清原因。
4. **体验优先**：一起看电影、选晚餐、亲子约会等体验型奖励通常比物品更适合长期习惯养成。
5. **共同修订**：每周家庭小会回看完成率，让孩子参与调整任务难度和奖励价格。规则越透明，越容易内化。
6. **慎用扣分**：扣分项应由家长孩子共同接受，说清具体行为边界。优先用提醒帮助孩子纠正，定期回看记录，必要时由家长开启新一轮警告。

## 目录

```text
public/        前端页面、样式、PWA 应用外壳
src/           数据库与日期规则
server.js      HTTP 服务与业务 API
scripts/       数据库备份、密码恢复
test/          Node.js 自动化测试
data/          运行后生成；包含家庭数据，请勿提交到 Git
```

所有密码以加盐 scrypt 哈希保存，登录使用 HttpOnly、SameSite Cookie。接口限定家庭角色权限，并对登录失败进行限流。
