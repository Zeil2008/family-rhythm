# 家庭节奏

> 把好习惯变成全家的日常。

[GitHub 仓库](https://github.com/Zeil2008/family-rhythm) · [MIT License](LICENSE)

家庭节奏是一套可自托管的多用户家庭日程与积分系统。家长发起约定、验收成果并管理奖励；孩子接受约定、提交完成结果、积累积分。

项目使用 Node.js、内置 `node:sqlite` 和原生前端实现，没有第三方运行时依赖。数据、成员照片和成果照片全部保存在家庭服务器上，不依赖云账户。

**关键词：** 家庭日程 · 多人任务 · 积分奖励 · 习惯养成 · 扣分警告 · 照片验收 · 自托管 · PWA

## 技术栈

- **服务端：** Node.js 22.5+、Node 内置 HTTP 与 SQLite
- **前端：** 原生 HTML / CSS / JavaScript，无打包步骤
- **数据库：** SQLite，自动创建表并升级已有数据库
- **部署：** Docker Compose、家庭服务器、NAS
- **访问方式：** 桌面浏览器、手机、iPad PWA
- **安全：** scrypt 密码哈希、HttpOnly Cookie、角色权限校验、登录限流

当前应用版本可通过以下接口查看：

```text
GET /api/version
```

## 任务规则

| 任务类型 | 创建与生效 | 修改规则 | 完成与积分 |
| --- | --- | --- | --- |
| 约定任务 | 家长创建，孩子接受后生效 | 清单由家长维护；家长修改后孩子需要重新接受 | 孩子按约定频次上报成果，家长验收通过后获得积分 |
| 自建任务 | 孩子创建，家长审核通过后生效 | 孩子可以修改自己创建的任务；修改已生效任务后会重新进入家长审核 | 按审核后的频次上报成果，家长验收通过后获得积分 |

### 多人日程

- 一个日程模板可以同时分配给多位家庭成员。
- 任务不会简单复制成多份互不关联的数据；所有成员共享同一份日程模板。
- 每位孩子需要分别接受约定，只有接受后才会看到自己的日程。
- 每位孩子独立提交成果，家长分别审核并分别发放积分。
- 家长修改已接受的多人约定后，所有相关孩子都需要重新确认。

### 成果验收

- 孩子可填写完成说明，并上传一张手机拍摄的成果照片。
- 照片在浏览器端压缩后上传，成员照片和成果照片仅家庭成员可访问。
- 家长通过后积分到账；退回时会保留审核意见，孩子可重新提交。
- 服务端会校验成员分配、接受状态和角色权限，不只依赖隐藏界面按钮。

## 功能概览

### 家庭与成员

- 家长和孩子使用独立数字密码登录。
- 支持添加多位家长和孩子，每位成员拥有独立积分和历史记录。
- 每位成员可自行上传、更换或移除照片头像；未设置照片时显示姓名首字。
- 家长可添加成员、修改称呼、重置密码、停用成员。

### 日程与验收

- 支持单次、每天、工作日和每周指定日期。
- 可设置分类、计划时间、开始日期、结束日期、积分和验收说明。
- 同一个日程模板可同时分配给多人，每人生成独立完成记录。
- 约定任务需要孩子接受；自建任务需要家长审核。
- 完成上报支持文字成果和手机照片。
- 家长可查看待审核成果，通过或退回。

### 积分与奖励

- 任务验收通过后自动增加积分。
- 每笔积分变化都有原因、类型、时间和调整后余额。
- 家长可手动增加或扣除成员积分，且不能把余额扣成负数。
- 支持奖励库存、所需积分、兑换申请、兑现、退回和取消退款。
- 奖励可设置 Emoji 图标、说明、金额和库存。

### 行为扣分约定

- 家长创建扣分项，设置具体行为说明、扣分分值和警告次数。
- 默认提供 3 次警告，孩子接受扣分约定后生效。
- 前 N 次记录只产生警告；警告次数用完后，后续记录才扣积分。
- 当前积分不足时最多扣到 0，不产生负积分。
- 家长可开启新一轮警告，所有警告、扣分和重置都会保留记录。

### 家庭数据

- 首页显示个人或全家今日进度、成员进度、积分和最近积分变化。
- 周日程视图按成员分组，可查看一周安排。
- 家庭页显示 7 天完成趋势、成员成长榜和家庭积分。
- 手机、iPad 和桌面浏览器自适应。
- 支持 PWA 和添加到主屏幕。

## 快速启动

需要 **Node.js 22.5 或更高版本**，推荐 Node.js 24。项目没有第三方 npm 依赖。

```powershell
node server.js
```

打开 <http://localhost:3000>，按首次设置页面创建家庭。服务同时监听局域网地址，启动日志会打印版本号和访问地址。

```text
家庭节奏 v1.2.1 已启动：http://localhost:3000
局域网访问：http://192.168.1.10:3000
```

手机或 iPad 连接同一个 Wi-Fi 后访问该地址即可。在 Safari 中选择“添加到主屏幕”，可以获得接近原生应用的入口。

首次设置建议：

1. 创建家庭名称和家长账号。
2. 创建至少一位孩子账号。
3. 设置 4–8 位数字密码。
4. 家长在“管理”中发起约定任务或多人日程。
5. 孩子登录后接受约定，再开始按频次提交成果。

开发时可以使用：

```powershell
node --watch server.js
```

运行自动化测试：

```powershell
node --test
```

验证运行中的版本：

```powershell
Invoke-RestMethod http://localhost:3000/api/version
```

正常会返回：

```json
{"version":"1.2.1","feature":"multi-assignee-schedule"}
```

## Docker 部署

安装 Docker 后，在项目目录运行：

```bash
docker compose up -d --build
```

默认访问地址是 `http://家庭服务器IP:3000`。

数据与照片通过 `./data:/app/data` 持久化：

```text
data/family.db
data/uploads/
```

停止和重新构建：

```bash
docker compose down
docker compose build --no-cache
docker compose up -d --force-recreate
docker compose logs -f
```

> `docker compose down` 不会删除宿主机上的 `./data`。不要使用带 `--volumes` 的删除命令。

如需修改端口，先复制 `.env.example` 为 `.env`，再修改 `APP_PORT`。

```bash
docker compose up -d --force-recreate
```

### NAS 部署

群晖 Container Manager、威联通 Container Station 和通用 Docker Compose 的步骤见 [NAS 部署指南](deploy/NAS-DEPLOY.md)。

群晖更新可以使用：

```bash
sudo sh /volume1/docker/family-rhythm/deploy/synology-update.sh
```

脚本会先停止容器、备份 `data`，然后无缓存重新构建并强制启动。其他安装路径需要先修改脚本中的 `APP_DIR`。

更新完成后检查：

```text
http://NAS局域网IP:3000/api/version
```

如果页面仍显示旧内容，而版本接口已经正确，请使用浏览器隐私窗口测试；PWA 用户可能需要删除旧主屏幕图标后重新添加。

## 建议使用 HTTPS

局域网 HTTP 已经可以正常使用，但安全 Cookie 和完整的 PWA 安装能力通常需要 HTTPS。家庭服务器可以通过 Caddy、Nginx、群晖反向代理或 Tailscale 提供安全访问。

`deploy/HTTPS.md` 包含群晖、威联通和 Caddy 的完整 HTTPS 配置步骤，`deploy/Caddyfile.example` 给出了 Caddy 配置示例。启用 HTTPS 后，在 `.env` 中设置：

```text
COOKIE_SECURE=true
```

设置后需要重新创建容器。不要把 `3000` 端口直接暴露到公网。需要跨网络访问时，优先使用 Tailscale、WireGuard 等家庭 VPN。

## 数据备份与恢复

需要备份的完整数据包括：

```text
data/family.db
data/uploads/avatars/     成员头像
data/uploads/             任务成果照片
```

建议每天预约一次在线备份：

```powershell
node scripts/backup.js
```

备份会写到 `data/backups/`，同时备份 `data/uploads/` 中的头像和成果照片。可以把整个 `data` 目录同步到 NAS 的另一块磁盘，但不要只复制正在写入的数据库文件；使用备份脚本更安全。

恢复时停止服务，将选定的数据库备份复制为 `data/family.db`，并把对应时间戳的 `uploads-*` 目录恢复为 `data/uploads`，再重新启动。也可以设置 `DB_PATH` 指向其他位置。

家长忘记密码时，停止服务并运行：

```powershell
$env:NEW_PIN="新的4到8位数字"
node scripts/reset-pin.js "爸爸"
```

脚本会同时清除该成员的旧登录会话。不要将密码放入会公开保存的脚本或聊天记录。

## 可配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_PORT` | `3000` | Docker Compose 映射到宿主机的端口 |
| `PORT` | `3000` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址，家庭局域网访问需保持默认 |
| `DB_PATH` | `data/family.db` | SQLite 数据库路径 |
| `UPLOAD_DIR` | 数据库目录下的 `uploads/` | 成员头像和成果照片保存目录 |
| `COOKIE_SECURE` | `false` | 使用 HTTPS 时设为 `true` |

## 积分机制建议

1. **小步、稳定**：每天 3–5 个核心任务即可。积分宁可小而稳定，不要用一次大额奖励制造压力。
2. **奖励过程**：除了结果，也给“主动开始”“自己检查”“遇到困难后重试”加分，让孩子看到可复制的行为。
3. **避免罚分绑定情绪**：没完成时先找原因，积分规则照常执行，但不要临场扣分惩罚。家长手动减分应少用，并写清原因。
4. **体验优先**：一起看电影、选晚餐、亲子约会等体验型奖励通常比物品更适合长期习惯养成。
5. **共同修订**：每周家庭小会回看完成率，让孩子参与调整任务难度和奖励价格。规则越透明，越容易内化。
6. **慎用扣分**：扣分项应由家长孩子共同接受，说清具体行为边界。优先用提醒帮助孩子纠正，定期回看记录，必要时由家长开启新一轮警告。

## 安全说明

- 密码以加盐 scrypt 哈希保存，服务端不保存明文密码。
- 登录使用 HttpOnly、SameSite Cookie，并对连续失败登录进行限流。
- 家长与孩子的管理权限在服务端校验。
- 成员头像和成果照片需要登录后才能访问。
- 公网部署必须使用 HTTPS，并设置 `COOKIE_SECURE=true`。
- 不要将 `data/`、`.env`、数据库或照片提交到 Git。
- 更新或迁移前先备份整个 `data` 目录。
